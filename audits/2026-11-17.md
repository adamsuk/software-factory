# Line audit: adamsuk software factory (guide 2026-11-12, run 2026-11-17)

**Headline:** 39 recommendations: **21 met · 16 partial · 2 missing · 0 unknown**
(Best practice 16: 15 met / 1 partial / 0 missing / 0 unknown. Cutting edge 23: 6 met / 15 partial / 2 missing / 0 unknown).

**Scope:** `adamsuk/software-factory` (main `d9a1ae7`), `adamsuk/gh-factory` (`35b16b6`), `adamsuk/activity-feed` (`6cde021`), `adamsuk/line` (`05414da`), `adamsuk/adamsuk` (`6fe7da1`). Evidence: the live guide JSON at `https://adamsuk.github.io/line/guide.json` (version 2026-11-12, 39 recommendations), fresh clones of those heads, `gh api` GETs of rulesets, environments, workflows, runs, releases, issues and the last 30 merged PRs per repo, secret and variable names only, and read-only Cloudflare API calls for the `activity-feed` Worker (script settings, deployments, schedules, alert policies, webhook destinations, telemetry and invocation analytics). No secret values were read or printed. Nothing was written to GitHub or Cloudflare during the audit.

**How this run was made:** by hand, read-only, with the `gh` CLI and the Cloudflare MCP connection, following the guide's audit prompt. It was not produced by `.github/workflows/line-audit.yml`: that workflow's four runs today ran only its gate job (`Should the audit run`) and skipped the audit, because `ANTHROPIC_API_KEY` and the `AUDITOR_*` variables are still unset.

**Most important gaps:**
1. **No production signal reaches the factory.** The `activity-feed` Worker has observability off (no `observability` in its script settings, no `[observability]` in `wrangler.toml`, a 7-day telemetry query returned no events), log push off and no tail consumers. The account's only alert policies are DDoS and a billing budget, both by email, and there are no webhook destinations. Filed as adamsuk/activity-feed#49.
2. **Tokens are not per run.** `scripts/gh-app-token.sh` caches one installation token for every installed repo until five minutes before it expires (#213, open).
3. **No merge queue.** GitHub does not offer one on user-owned repos. The maintainer accepted the substitute on 2026-11-17 (#312): every `factory-main` ruleset requires branches to be up to date, with required checks on GitHub-hosted runners.

## (c) Biggest gains

Best practice:
1. **clean-runner-merge-queue (M/L).** First step: move one repo (activity-feed) into an organisation and turn on GitHub's merge queue for it. Tools: GitHub merge queue, Trunk Merge Queue, Mergify (all Partial).

Cutting edge:
1. **signal-to-work-order (H/M).** First step: `[observability] enabled = true` in activity-feed `wrangler.toml`, then a Workers Observability alert delivered through a verified relay that opens `factory:triage` issues (adamsuk/activity-feed#49). Tools: none listed.
2. **verify-after-deploy (H/M).** First step: let a work order carry one request/response check and run it after activity-feed's promote step; hold `factory:done` on it (#231). Tools: none listed.
3. **per-run-credentials (H/M).** First step: mint the installation token per work order with `repositories` set to the target repo, without the cache (#213). Tools: none listed.
4. **harness-evals (M/M).** First step: replay a small set of recorded work orders on every brief or model change and log the pass rate. Tools: Inspect AI, Promptfoo (Full); Braintrust (Partial).
5. **qa-agent (M/M).** First step: a bench step where a second agent writes tests to break the change before handoff. Tools: none listed.
