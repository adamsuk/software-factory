## (b) Quick wins (impact H or M, effort S)

### Best practice

1. **`human-approves` (H/S).** Stop a bot review from satisfying `approvals: 1`, and stop the owner `pull_request` bypass from merging over a missing human APPROVED review. `line` #60 is the proof a bot approval is enough today; `software-factory` #205 is the proof the bypass merges `CHANGES_REQUESTED`.
2. **`checks-not-claims` (H/S).** Add `test` and `changelog` to the `line` ruleset. `test.yml` and `.github/factory.yml` already name them. A failing Test run can merge until that list is on the ruleset.
3. **`human-release-gate` (H/S).** Add a required reviewer to the `github-pages` environment, and put the `activity-feed` wrangler step in an environment that has one. Rollback steps for each belong in the same change.
4. **`egress-allowlist` (H/S).** Add SHA-pinned Harden-Runner to the workflows that have none (`software-factory` lint, changelog, line-audit, ruleset-drift; `line` test, pages, codeql, changelog; `activity-feed` deploy, codeql, changelog). `gh-factory` is already on `egress-policy: audit`; the follow-on is an allowlist that blocks.
5. **`owned-instructions` (M/S).** Set `require_code_owner_review` true on each `factory-main` ruleset so a change to `AGENTS.md`, `agents/**` or `.github/` needs the owner review the CODEOWNERS file already names.

### Cutting edge

1. **`tests-out-of-reach` (M/S).** Add the `Test assertions` check to `software-factory` `required_checks` and to ruleset 26119160. The job already runs on pull requests.
2. **`review-record` (M/S).** Extend `ir_post_comment` so the watcher comment carries the four fields and the full head SHA. The brief already says the station-run path must, and that the watcher does not.
3. **`spec-drift` (M/S).** Give the Monday job a read-only token (`FACTORY_READ_TOKEN` is unset; the sampled run failed on an empty `GH_TOKEN`) and make a ruleset that omits `factory.yml` `required_checks` fail the job. `line` is the current miss.
4. **`audit-with-mcp` (M/S).** The cron is already there. The sampled run failed closed on `ANTHROPIC_API_KEY` and `AUDITOR_GUIDE_URL`, `AUDITOR_GUIDE_VERSION`, `AUDITOR_CLI_VERSION`. Set those, or disable the workflow and reopen `#21`. The guide's shape is an MCP-connected read-only pass; this workflow is Claude Code.
5. **`measure-review-bot` (M/S).** Run `scripts/review-bot-metrics.sh` in the weekly monitor write-up. The script exists and is uncalled. The monitor publish itself is a separate gap (`measure-factory`).

## (c) Biggest gains

### Best practice

1. **`human-approves`.** First step: change ruleset 26119160 (and the `gh-factory` and `activity-feed` copies) so the owner's bypass does not skip the approving review, and so `coderabbitai` does not count toward `approvals: 1`. Then merge an app PR only after an `adamsuk` APPROVED review on that head, which `#208` and `line` `#69` already did. Tools: GitHub rulesets (Full), Copilot code review (Partial).
2. **`checks-not-claims`.** First step: put `test` and `changelog` on the `line` ruleset, then add a `pull_request` test job to `activity-feed` and require it. The deploy-time test leaves main carrying untested commits. Tools: GitHub rulesets (Full), Trunk Merge Queue (Full), Mergify (Full).
3. **`sandbox-no-secrets`.** First step: run the bench in a fresh container with no `--always-approve`, and keep the app token out of that container the way `run-work-order.sh` already strips it from the `grok` child. Tools: E2B (Full), Daytona (Full), Copilot coding agent (Full).
4. **`egress-allowlist`.** First step: switch `gh-factory` Harden-Runner from `audit` to an allowlist that blocks, then add the same action to the other enrolled workflows and to the box the watcher runs on. Tools: Copilot coding agent firewall (Full), StepSecurity Harden-Runner (Full).
5. **`human-release-gate`.** First step: required reviewers on `github-pages` and on a new `activity-feed` production environment, then do one rollback of each and write down the commands. Tools: GitHub environments (Full).
