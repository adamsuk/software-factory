**Scope:** `adamsuk/software-factory` (main `7dd8782`, 11 Nov), `adamsuk/gh-factory` (`45fa314`), `adamsuk/line` (`b3fd015`), `adamsuk/activity-feed` (`f59e1c4`), `adamsuk/adamsuk` (`8754b93`). **Baseline note:** the 3 Nov audit scored 29 recommendations. This run scores all 39 in the guide. **Most important fixes:**
1. **No deploy path rebuilds-once-and-promotes, and nothing checks the live result.** `activity-feed` `deploy.yml` re-tests and runs `wrangler-action` from source on each push, and its actions are not SHA-pinned (`actions/checkout@v7`, `cloudflare/wrangler-action@v4`). `line` builds once per run but has a single environment. No work order records a post-deploy check (`verify-after-deploy`, #231).
2. **Egress is still audit-only outside `gh-factory`.** `gh-factory` is `egress-policy: block` on 8 workflows. Its `release.yml` and `mutation.yml` stay on `audit` (#321). Every workflow in `software-factory`, `line` and `activity-feed` is `audit`. The work-order bench still runs `grok --always-approve --sandbox workspace` on the shared box (`scripts/run-work-order.sh:733`, #221).
3. **The monthly Line audit workflow cannot run itself.** Actions secrets on `software-factory` are `["FACTORY_READ_TOKEN"]` and variables are `[]`, so `ANTHROPIC_API_KEY` and `AUDITOR_*` are unset. The header of `.github/workflows/line-audit.yml` still says "NOT YET RUNNABLE".

## (c) Biggest gains

### Best practice

1. **`promote-not-rebuild` (H/L).** First step: split `activity-feed` `deploy.yml` into a build job that uploads one artifact and a deploy job that publishes that artifact to `production`, and pin its actions by SHA (#324). Tools per the guide: build systems that pin and promote a digest, no listed product does it by default.
2. **`sandbox-no-secrets` (H/L).** First step: run the bench in a fresh container without `--always-approve` (#221). Tools: E2B, Daytona, Copilot coding agent.
3. **`egress-allowlist` (H/M).** First step: switch `gh-factory` `release.yml` and `mutation.yml` from audit to block (#321), then add endpoint lists for `software-factory`, `line` and `activity-feed` from the audit logs. Tools: StepSecurity Harden-Runner, Copilot coding agent firewall.
4. **`clean-runner-merge-queue` (M/L).** First step: keep `merge_group` triggers and move to an organisation-owned repo or a third-party queue, since GitHub merge queue cannot be enabled on user-owned repos (#312 deferred). Tools: Trunk Merge Queue, Mergify.
5. **`progressive-release` (M/L).** First step: Cloudflare gradual deployment for the `activity-feed` Worker with a named guardrail (#308 deferred). Tools: Argo Rollouts, LaunchDarkly, per the guide.

### Cutting edge

1. **`verify-after-deploy` (M/M).** First step: a work order field naming one request and the expected response, run after the `line` Pages and `activity-feed` deploys, with `factory:done` withheld until it passes (#231).
2. **`per-run-credentials` (H/L).** First step: mint a token per work order scoped to the order's repo, with `expires_at` under an hour, and stop reusing the cache (#213).
3. **`attest-provenance` (M/M).** First step: remove `continue-on-error` on the `release.yml` attest step and verify before any promote (#229).
4. **`tests-out-of-reach` (M/M).** First step: extend the assertion check to skipped and silently-dropped tests in `gh-factory` and `line` (#113).
5. **`spec-signs-off` (M/L).** First step: generate checks from the work order criteria and make that result the sign-off (#22).
