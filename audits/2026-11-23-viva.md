# Viva audit: skills and MVP platform against the research (run 2026-11-23)

**Headline:** 13 findings, filed as 13 tickets (#457 to #469) beside 3 onboarding tickets (#454 to #456). **2 P0** (privacy and persistence broke the MVP's own promises), **8 P1**, **4 P2**, **1 P3** (onboarding included). Every ticket has a pull request open; none is merged.

**Scope:** `adamsuk/viva` (main `8386503`: the research site and the personal-map MVP, `docs/mvp-platform.md`) and `adamsuk/viva-skills` (main `c98b152`: `viva` 0.3.3, `viva-assess` 0.1.5). The yardstick is Viva's own research: the 23 recommendations and 43 labelled claims in `src/viva/model.ts` (published as `docs/recommendations.md`, `docs/claims.md`, `docs/prior-art.md`), plus the MVP's own scope table and success criteria. The live site and `log-schemas.json` were fetched (both 200). `npm run typecheck && npm run lint && npm test` passed on main (44 tests).

**How this run was made:** by hand in a Claude Code cloud session, at the maintainer's request ("onboard viva and viva-skills, audit the skills and MVP platform against the research, create and prioritise tickets, then ticket through them"). The factory's station containers, the egress proxy and the bot's GitHub App token are not available in that session, so it acted as each station by hand under AGENTS.md: intake (issues filed `factory:ready` with one `Target repo:` line, checkable criteria and a size), foreman (work orders in `agents/work-orders/`), builder (one `factory/<issue>-<slug>` branch and PR per issue, tests and a CHANGELOG entry each), gate (the repo's test command run locally) and an independent review of each diff. It never approved or merged anything.

## Most important gaps

1. **The skills' README told users their answers go to a GitHub gist by default** (`private-by-default`, Best practice). Both `SKILL.md` files say the opposite (device-local). The research is Strong that monitoring without a transparent purpose goes with worse attitudes. #457.
2. **The personal map forgot everything on reload**, though both skills tell users without a filesystem that the map stores the log in the browser (IndexedDB). The "private, longitudinal map" is the open ground prior art names; on the site it could not accumulate at all. #458.
3. **The log contract was already broken**: the skill writes `0.3.3`, the platform only knew `0.3.1`, and lookup was exact. Malformed lines vanished without a count. #459.
4. **The single strongest finding in the claims was not captured**: how AI was used (delegation vs asking why) predicted understanding in the Anthropic RCT. The log had no field for it, so the map could not show it. #464, #465.

## Engineering and factory findings

- Neither repo was enrolled: no `.github/factory.yml`, `AGENTS.md`, `CODEOWNERS`, task template or size label (#455, #456). viva-skills had no CI, tests or CHANGELOG at all; nothing checked that a skill's "currently X" or example log line matched its `metadata.version` (#456 adds `scripts/validate-skills.sh`).
- viva `pages.yml` used tag refs and gave `pages: write` and `id-token: write` to pull-request builds; `test.yml` ran only on PRs into `main` (#469, protected).
- The factory's default repo list did not know either repo (#454).

## Merge order

Merge each stack bottom-up with merge commits (both repos use them), deleting each branch so GitHub retargets the next PR to `main`.
