# Line audit: a private organisation (guide v2026-10-24, run 24 Oct 2026)

**Headline:** 24 recommendations: **2 met · 12 partial · 8 missing · 2 unknown** (Best practice 12: 0 met / 5 partial / 6 missing / 1 unknown; Cutting edge 12: 2 met / 7 partial / 2 missing / 1 unknown).
**The most important fix:** the delivery app `main` ruleset only blocks deletion and force-push. Add "require a pull request" and required status checks (Tests with coverage, E2E against a local preview build, Analyze), then copy the ruleset to a private repo, the second delivery app and .github, which have no rules at all.
**The structural blocker:** agents act under the repository owner's own identity, holding a token scoped broadly rather than least-privilege (the exact scope list is withheld here). Nothing technical stops an agent pushing to main, and GitHub can't require a human approval because Scott can't approve PRs that carry his own name.

Scope: the delivery app, the second delivery app, a private repo, .github and an additional private repository sample (private, no rulesets on the Free plan), all non-archived. CI sample: the last 100 runs per repo. For the delivery app that only reaches back to 20 Oct, because Dependabot runs are noisy. PR sample: the last 30 the delivery app PRs. Cloudflare: Workers list only. The delivery app and a private repo deploy to **Cloudflare Pages**, which these MCP servers can't see. A PostHog analytics project.

## (b) Quick wins (impact H/M, effort S)
**Best practice**
1. **Require PRs and checks on main** (checks-not-claims, staged-writes, H/S). In the delivery app's `main` ruleset, add `pull_request` (0 approvals for now) and `required_status_checks` (Tests with coverage, E2E against a local preview build, Analyze (javascript-typescript)). Then copy it to a private repo, the second delivery app and .github.
2. **Production approval gate** (human-release-gate, H/S). Create a `production` environment with Scott as required reviewer, and put the prod deploy job in `main.yml` behind `environment: production`. Do a rollback drill on a Pages deployment.
3. **CODEOWNERS** (owned-instructions, M/S). Add `* @adamsuk`, with `.claude/**`, `.github/**`, `package-lock.json`, `**/__tests__/**`, `e2e/**` called out. It only enforces once the ruleset requires code-owner review, so do it after #2 in (c).
4. **Issue form template** (done-as-checks, M/S). Add `.github/ISSUE_TEMPLATE/work-order.yml` to the org `.github` repo, with required "Acceptance criteria (checks)" and "Out of scope" fields.

**Cutting edge (options)**
- measure-review-bot (M/S): add `.coderabbit.yaml` and log accepted or dismissed CodeRabbit comments per PR.
- fix-paths-to-person (M/S): this comes free with CODEOWNERS plus code-owner review.
- attest-provenance (M/S): build once, add `actions/attest-build-provenance` on the dist tarball, and deploy that same tarball.

## (c) Biggest gains
**Best practice**
1. **Give agents their own identity and sandbox** (sandbox-no-secrets, egress-allowlist, human-approves; H). First step: create a GitHub App, or a bot user, for Issue Shipper and PR Reviewer with `contents`/`pull_requests` write on named repos only, and remove the owner token from the agent runtime. Scott can then *approve* agent PRs, and agents can't push to main or edit workflows. Tools: E2B (Full), Daytona (Full), Copilot coding agent (Full); for egress, Copilot coding agent firewall (Full) and StepSecurity Harden-Runner (Full); GitHub rulesets (Full) for approval.
2. **Enforce the gate** (checks-not-claims, staged-writes; H). First step: quick win #1. Tools: GitHub rulesets (Full), Trunk Merge Queue (Full), Mergify (Full); GitHub Agentic Workflows (Full) for staged writes.
3. **Gate and stage production** (human-release-gate, progressive-release; H). First step: add the `production` environment, then wrap risky features (billing, Direct Debits #276, auth) in PostHog flags and roll them out by percentage. Tools: GitHub environments (Full); LaunchDarkly guarded rollouts, Argo Rollouts, Flagger (Full; the last two are Kubernetes-oriented and don't fit Pages).
4. **Measure the factory** (measure-factory; M). First step: a PostHog alert on error-rate and on the `$exception` trend, plus a weekly script over `gh` deployments and runs to compute change failure rate and time to restore. Tools: DX, Faros AI, Swarmia (Partial).
5. **Scale review to risk** (scale-review; M). First step: a size label workflow, and a rule that PRs over 400 lines or touching auth or billing need deep human review. Tools: Graphite, PullApprove (Partial).

**Cutting edge (options)**
- harness-evals: replay 5–10 past issues (e.g. #251, #261) through Issue Shipper whenever its prompt changes. Tools: Promptfoo, Inspect AI (Full), Braintrust (Partial).
- triage-red-checks / check-the-checks: Trunk Flaky Tests, Nx Cloud self-healing CI (Partial); Stryker mutation testing on `functions/` (Partial).
- spec-drift: extend the schema-diff pattern to docs. Tools: dependency-cruiser, ArchUnit (Partial).
- audit-with-mcp: schedule this audit monthly. Tools: GitHub MCP Server, Datadog MCP Server (Partial).
