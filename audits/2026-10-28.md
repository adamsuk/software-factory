# Line audit: adamsuk/software-factory (guide v2026-10-27, run 28 Oct 2026)

**Headline:** 27 recommendations: **2 met · 13 partial · 12 missing · 0 unknown**
(Best practice 12: 0 met / 6 partial / 6 missing; Cutting edge 15: 2 met / 7 partial / 6 missing).

**Scope:** `adamsuk/software-factory` only, as both subject and implementer — this repo
holds the agent rules, the station runner and the work-order runner, so a gap here is a
gap in every station it drives. Read-only `gh api` GETs, `gh pr/run/issue/release list`.
PR sample: all 37 merged PRs. CI sample: last 100 runs. No secret values were read or
printed.

**Most important fix:** the gate verifies nothing about behaviour. Seven test scripts
(`scripts/test-*.sh`) exist and **none runs in any workflow**; `.github/factory.yml`
declares `test_command: shellcheck scripts/*.sh`, a linter. Every agent claim of "done"
on a behavioural change is therefore unverified by the gate.

**Second:** no independent human approval has ever happened here. Across 37 merged PRs
the only reviewers are `coderabbitai` (a bot) and `adamsuk` (the author, self-reviewing
#41, #55, #56, #57, #58). Ten merged with `CHANGES_REQUESTED` standing and seven with no
review at all.

**Structural blocker:** the repo is private on a Free user plan, so rulesets and branch
protection return **HTTP 403**. Four Best practice recommendations (`staged-writes`,
`checks-not-claims`, `human-approves`, and the enforcement half of `fix-paths-to-person`)
cannot be enforced until that changes (#112).

## (b) Quick wins (impact H or M, effort S)

### Best practice
1. **`checks-not-claims` (H/S)** — add the seven `scripts/test-*.sh` to `lint.yml` and
   name them in `factory.yml`'s `required_checks`. The scripts already exist and are
   self-contained (they use a fake `gh` and do not contact GitHub).
2. **`human-approves` (H/S)** — require one independent approval that is not the author's
   and not a bot's, and record the Grok Build verdict on the PR head.
3. **`egress-allowlist` (H/S)** — add StepSecurity Harden-Runner to both workflows.
4. **`staged-writes` (H/S)** — decide the Free-plan question (#112): make the repo public
   or upgrade to Pro. Four Best practice items are blocked behind it.
5. **`scale-review` (M/S)** — set a changed-lines budget per PR and reopen #15.

### Cutting edge
1. **`review-record` (M/S)** — publish the four-field record (#119, #97).
2. **`audit-with-mcp` (M/S)** — put this audit on a monthly cron (#21).
3. **`fix-paths-to-person` (M/S)** — follows free once code-owner review is enforceable.

## (c) Biggest gains

### Best practice
1. **`checks-not-claims`** — first step: a `tests` job in `lint.yml` running the seven
   scripts. Tools: GitHub rulesets (Full), Trunk Merge Queue (Full), Mergify (Full).
2. **`human-approves`** — first step: write the "independent approver" rule into
   AGENTS.md §6 and stop treating a self-review as an approval. Tools: GitHub rulesets
   (Full), Copilot code review (Partial).
3. **`sandbox-no-secrets`** — first step: a `.devcontainer` for agent runs, then drop
   `--always-approve`. Tools: E2B (Full), Daytona (Full), Copilot coding agent (Full).
4. **`human-release-gate`** — first step: pin agents to a released tag instead of
   `origin/main`, so promotion is a step a person takes. Tools: GitHub environments (Full).
5. **`egress-allowlist`** — first step: Harden-Runner in audit mode, then block.
   Tools: Copilot coding agent firewall (Full), StepSecurity Harden-Runner (Full).

### Cutting edge
1. **`harness-evals`** — first step: run `lint-prompts.sh` in CI, then add a task set
   replayed on every prompt change. Tools: Inspect AI (Full), Promptfoo (Full).
2. **`spec-drift`** — first step: a check that `factory.yml`'s `test_command` and the
   role briefs' script refs resolve to files that exist on `main`.
   Tools: dependency-cruiser (Partial), ArchUnit (Partial).
3. **`review-record`** — first step: a PR-template section plus a CI check that it is
   filled in and names the head commit.
4. **`triage-red-checks`** — first step: record each red check's job, cause and
   seen-before flag. Tools: Trunk Flaky Tests (Partial), Nx Cloud self-healing CI (Partial).
5. **`check-the-checks`** — first step: mutation-test the shell helpers (#23).
   Tools: Stryker (Partial).

Every score above is evidenced; none is unknown. What I could **not** see, and what
would let me check it:

- **Grok Bot agent configs** (Issue Shipper, PR Reviewer, Signal Issues, Research Scout)
  live outside any repo, so I could only score the written briefs, not the running
  configuration. Access needed: the configs committed to a repo, or a read-only export.

  `run-work-order.sh`, not the machine. Access needed: shell or inventory access to the
  box, or a devcontainer definition in the repo to score instead.
- **CodeRabbit comment acceptance rates.** Access needed: the CodeRabbit dashboard or API.
- **Whether a Grok Build review verdict was ever actually produced** for the 17 PRs
  merged without a standing approval. Access needed: the verdicts published on the PRs,
  which is #119 itself.
