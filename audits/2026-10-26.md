## (c) Biggest gains

**Best practice**
1. **One gate on every delivery repo** (checks-not-claims, staged-writes, owned-instructions; H). First step: enrol [private reference redacted] (#2), then [private reference redacted] and touchlineHQ (#35, #36). Tools: GitHub rulesets (Full), CODEOWNERS (Full).
2. **Agents get their own identity and sandbox** (sandbox-no-secrets, egress-allowlist, human-approves; H). First step: a GitHub App or machine user for the bots so approvals and merges are attributable, then `approvals: 1`. Tools: Copilot coding agent (Full), E2B or Daytona (Full) for sandboxes, StepSecurity Harden-Runner (Full) for CI egress. (#7, #8, #9)
3. **Gate and stage production** (human-release-gate, progressive-release; H). First step: the `production` environment, then a PostHog flag on the next billing change. Tools: GitHub environments (Full), LaunchDarkly guarded rollouts (Full), or PostHog flags (not in the guide). (#37 to #40)
4. **Measure the factory** (measure-factory; M). First step: a weekly job that counts the shared `factory:*` status labels, PR lead time, first-time-green rate, review rounds, fix attempts and Grok cost. Tools: DX, Swarmia, Faros AI (all Partial). (#14)
5. **Standard triage across repos** (done-as-checks, untrusted-issues; M). First step: the shared status labels in the gh-factory baseline and a triage brief. Tools: GitHub Spec Kit, Kiro (Partial).

**Cutting edge (options)**
- harness-evals: replay a handful of past work orders when a brief or model changes (Promptfoo, Inspect AI: Full). (#20)
- review-capacity: cap open agent PRs per repo and track time to first review (DX, Swarmia: Partial).
- triage-red-checks: a flake record per check name (Trunk Flaky Tests: Partial). (#24)
- spec-drift: check that briefs match `scripts/run-work-order.sh` flags. (#28)
- audit-with-mcp: schedule this audit (#21).
